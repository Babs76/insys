## What this batch builds

### Function catalogue (ADR-026, signed off with six changes)
- **Catalogue:** 549 functions in 14 domains and 80 sub-domains, generated into `R__function_catalogue.sql` from each module's `Functions.cs` and the permissions its endpoints require (`FunctionCatalogueTests` fails when it is stale, when a function names an operation the build lacks, or when a JOB function runs nowhere).
  - The 12 domains and 54 sub-domains of `INSYS_NAVIGATION.md`, PORTALS (`BROKER_PORTAL`, `PROVIDER_PORTAL`, `CUSTOMER_PORTAL`) and CONFIGURATION (one sub-domain per INSYS module).
  - Static data: view, maintain and approve per catalogue module: 58 modules, 174 functions (**please confirm, OQ-095**: per sub-module would be almost per table).
  - 15 JOB functions (OQ-098). Names are the `labels` column; tenants cannot rename.
- **Access:** a user's permissions are those their functions require. Order of checks: tenant status (Onboarding: only functions open then), platform availability, tenant enablement (`FUNCTION_DISABLED`), feature entitlement (`FEATURE_NOT_ENTITLED`), the user's grant (`FUNCTION_NOT_GRANTED`), then the permission, F103 and F005.
- **Menu:** `GET /identity/me/menu`, by audience and tenant status, in catalogue order, labels in the request language.
- **Governance:** a role holding a privileged function is privileged and needs MFA (`MFA_REQUIRED`, OQ-097); SoD rules pair functions; channel rows name functions; caches are evicted on activation.
- **Jobs:** a disabled JOB function parks its consumers' deliveries (`FUNCTION_DISABLED`) and its daily jobs skip the tenant.
- **Conversion (V0052, R__):** roles, SoD rules and channel rows are converted; existing tenants are entitled to every feature. Six screens whose reads needed two permissions were split so nothing is lost; the one exception is a role with only one of static data create and update (**OQ-096**). The before-and-after test covers the platform's role sets and every permission on its own.

### Communications follow-ups
- Marketing notifications record the consent record in force when sent (`consentRecordId`, V0053).
- `GET /claims/claims/{claimNumber}/communications` lists a claim's communications.
- `POST /payments/callback-endpoints` requires `Idempotency-Key` (breaking, listed).
- **Found and fixed:** the idempotency store kept a callback endpoint's signing secret in plain text for replay (Communications, merged in batch 2). Neither endpoint now stores the body; a repeat is refused (409 `IDEMPOTENCY_RESPONSE_NOT_KEPT`).

### CI: splitting the integration job
- **Now:** 20.5 minutes on batch 2 (limit 45); this batch adds about 20 tests.
- **Trigger:** split when a run passes 30 minutes.
- **Plan:** a matrix of two (then three) integration jobs, each with its own PostgreSQL container, selected by test class with `--filter-class` lists kept in `ci.yml`, balanced by the per-class times the test log reports. A check fails when a class is in no list or in two, so no test is dropped. The sweeps and end-to-end job stays as it is.

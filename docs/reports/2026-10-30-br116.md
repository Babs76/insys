# BR-116: the portal renewal read returns its ETag, 30 October 2026

**Defect.** Portal accept and decline require `If-Match`, but the portal read gave neither an ETag nor a `rowVersion`, so no member or broker could answer a renewal. The end-to-end test hid it by using the version from the staff read.

**Fix.** `PortalRenewalView` has `rowVersion`, and the read, accept and decline return the `ETag`. The test now reads as the member, accepts with that ETag, and gets 412 on a stale one.

**Sweep and guard.** `EveryIfMatchOperation_HasAReadByTheSameCaller_GivingItsVersion_BR116` (architecture) covers all three API documents: every `If-Match` operation has a read on its own path or a parent, in the same area, that gives an ETag or a `rowVersion`. A sweep of the document on main found only these two portal operations. The preference operations pass as they are: `If-Match` is optional there and each list item has its `rowVersion`.

The rule cannot tell whether two routes on the same path have different permissions; it matches by path, so a portal operation must find its read within the portal.

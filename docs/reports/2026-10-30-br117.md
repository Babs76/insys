# BR-117: the appointment letter's function, 30 October 2026

**Defect.** `GeneralRecordAppointmentLetter` declared a permission but no function. The channel check looks its rules up by function, so in a channel-enabled tenant it refused every caller, and no broker of record change could be submitted. The function check also skips a route with no function, so this route skipped the tenant status, enablement and feature checks.

**Fix.** The route is under `GENERAL_DRAFT_ENDORSEMENT`, the same permission: recording the letter is part of drafting. No new role or channel rule is needed. **Front end:** the operation's `x-function` is now `GENERAL_DRAFT_ENDORSEMENT`.

**Guard.** `EveryPermissionedRoute_DeclaresAFunctionInTheCatalogue_BR117`: every route with a permission declares a function in the catalogue. This is wider than the channel check, because of the skipped function check. Routes for any signed-in user and signed provider callbacks have neither, by design.

**What it found.** Only the letter route. On the route as it was, it fails and names `POST /general/endorsements/{id}/appointment-letter`.

**Test.** `ABrokerOfRecordChange_TakesItsLetterAndIsSubmitted_InAChannelEnabledTenant_BR117`.
